2.1Characteristics of data@@s2-1@@

🗣 In simple words
Before analysing any data, ask 3 questions: What is it made of? (Composition) · Is it in good shape? (Condition) · Where and why did it come from? (Context).

Data has three characteristics:

  1. Composition — deals with the structure of data: the sources of data, the granularity, the types, and the nature of data — whether it is static or real-time streaming.
  2. Condition — deals with the state of the data: "Can one use this data as is for analysis?" or "Does it require cleansing for further enhancement and enrichment?"
  3. Context — deals with "Where has this data been generated?", "Why was this data generated?", and so on.
Figure 2.1 — Characteristics of data
🧠 Memory trick
The 3 Cs of data: Composition (what), Condition (how good), Context (where & why).

2.4Challenges with Big Data@@s2-4@@

  1. Huge growth of data — data is growing exponentially, so it is difficult to decide which data is useful and which is noise. We must select relevant data for analysis.
  2. Cloud computing & virtualisation — cloud helps manage Big Data infrastructure efficiently: cost-effective, flexible, easy upgrading or downgrading of resources. (Challenge: deciding whether/how to host data on the cloud.)
  3. Data retention — deciding how long to store Big Data. Some data is useful for long-term decisions; some becomes irrelevant quickly.
  4. Lack of skilled professionals — shortage of experts in data science and Big Data technologies → hard to implement Big Data solutions.
  5. Data capture, storage, processing & security — challenges in capturing, storing, preparing, searching, analysing, transferring, securing and visualising data. Traditional databases may not handle data that is very large, fast and varied.
  6. Data visualisation — representing Big Data with graphs, charts, dashboards helps people see patterns. There is a shortage of skilled visualisation professionals too.

2.5What is Big Data? — the 3 Vs@@s2-5@@

Definition

Big data is data that is big in volume, velocity, and variety.

Figure 2.4 — Data: big in volume, velocity and variety
📦 Volume — how MUCH data

Huge amounts — from GB/TB to PB, EB, ZB. Comes from internal & external sources.

⚡ Velocity — how FAST data arrives

Batch → Periodic → Near real time → Real-time processing.

🎨 Variety — how many KINDS of data

Structured + semi-structured + unstructured, from many sources.

🧠 Memory trick
Imagine a river: Volume = how much water, Velocity = how fast it flows, Variety = how many different things are floating in it.

Variety — the kinds of data

Variety deals with a wide range of data types and sources:

  1. Structured data: from traditional transaction processing systems and RDBMS, etc.
  2. Semi-structured data: e.g., HyperText Markup Language (HTML), eXtensible Markup Language (XML).
  3. Unstructured data: e.g., unstructured text documents, audios, videos, emails, photos, PDFs, social media, etc.

2.6Other characteristics of data@@s2-6@@

These are not definitional traits of Big Data (the definition only needs the 3 Vs), but are still important:

✅ Veracity & Validity

Veracity = trustworthiness of data (is there noise, bias or abnormality?).
Validity = accuracy and correctness of data for the given problem.

e.g., fake reviews reduce veracity.
⏳ Volatility

How long the data remains valid and useful. Helps decide storage duration — some data stays useful for long, some becomes obsolete quickly.

e.g., today's stock price is stale tomorrow; birth date never expires.
📉 Variability

Data flow is inconsistent and can have sudden peaks. Systems must handle such irregular, fluctuating data rates.

e.g., traffic spike on a shopping site during a festival sale.
🔑 Key point
Core Big Data = 3 Vs (Volume, Velocity, Variety). The "extra" characteristics = Veracity & Validity, Volatility, Variability — together often called the 6 Vs.
⚠️ Common mistake
Velocity (speed of arrival) ≠ Variability (inconsistency of the flow) ≠ Volatility (how long data stays useful). Learn one example for each.

2.8Traditional Business Intelligence (BI) vs Big Data@@s2-8@@

🗣 In simple words
Business Intelligence (BI) = the old way: a company keeps its own neat (structured) data on one big central server and makes reports about the past. Big Data = the new way: data of all kinds, from inside and outside, spread over many cheap machines, analysed in real time too.

Three textbook differences (write these in a long answer):

  1. In traditional BI, all the enterprise's data is housed in a central server, whereas in Big Data it resides in a distributed file system. The distributed file system scales horizontally (scaling in or out), compared to a typical database server that scales vertically.
  2. In traditional BI, data is generally analysed in an offline mode; in Big Data, it is analysed in both real time and offline mode.
  3. Traditional BI is about structured data, and here data is taken to the processing functions; Big Data is about variety, and here the processing functions are taken to the data.

💡 Schema-on-write vs schema-on-read
Schema-on-write (BI): you must define the table structure before storing data — data that doesn't fit is rejected. Schema-on-read (Big Data): store the raw data first in any form; apply a structure only when you read/analyse it. This is why Big Data handles variety easily.
