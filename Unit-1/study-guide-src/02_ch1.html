1.1What is data?@@s1-1@@

🗣 In simple words
Data = raw facts. Numbers, words, pictures, sounds — anything a computer can store and work on. On its own data may not mean much; once we organise it, it becomes information, and when we understand it, it gives insights.
Definition

Data is the quantities, characters, or symbols on which operations are performed by a computer, which may be stored and transmitted in the form of electrical signals and recorded on magnetic, optical, or mechanical recording media.

Data comes from…

Data can be numbersfactsquantitiesinformationgraphsobservationsmeasurements

Computer data as information

  • Computer data is information processed or stored by a computer.
  • It may be text documents, images, audio clips, software programs, or other types of data.
  • It is processed by the computer's CPU and stored in files and folders on the hard disk.

Where does data live?

  • Data is present internal to the enterprise and also exists outside the four walls and firewalls of the enterprise.
  • Data is present in homogeneous sources (all of the same kind) as well as in heterogeneous sources (of many different kinds).

1.2Classification of digital data@@s1-2@@

🗣 In simple words
Think of three cupboards. Structured = everything in labelled boxes in neat rows (an Excel sheet). Semi-structured = items with name-tags but no fixed boxes (an XML/JSON file, an email header). Unstructured = everything thrown in a pile (photos, videos, chats).
Figure 1.1 — The three types of digital data
🔑 Key point
About 80–90% of an organisation's data is unstructured. Only a small part is neatly structured. This is the main reason we need Big Data tools.

1.3Structured data@@s1-3@@

Definition

Structured data is data which is in an organised form (e.g., in rows and columns) and can be easily used by a computer program. Relationships exist between entities of data, such as classes and their objects.

Example: data stored in databases.

Structured data and RDBMS

  • Most structured data is held in an RDBMS (Relational Database Management System — e.g., Oracle, MySQL, SQL Server, DB2).
  • An RDBMS follows the relational data model: data is stored in rows/columns (a table is also called a relation).
  • The number of rows/records/tuples in a relation = cardinality of the relation.
  • The number of columns = degree of the relation.
🧠 Memory trick
Cardinality = Count of rows (records). Degree = Down-the-top columns (attributes). Rows go "card by card", columns give the table its "degree" of detail.

How do we design structured data? (steps)

  1. Design the relation/table — decide the fields/columns and the type of data each will store: number (integer or real), alphabets, date, Boolean, etc.
  2. Decide the constraints the data must follow:
    • UNIQUE values in a column, NOT NULL values in a column,
    • a business constraint e.g., value in a column should not drop below 50,
    • a set of permissible values e.g., the column should accept only "CS", "IS", "MS".
  3. Relate tables to each other using common columns.

Sources of structured data

Ease of working with structured data

Structured data is the easiest type to work with. Your slides list 5 reasons:

✏️1. Insert / Update / Delete

The DML (Data Manipulation Language) operations make it easy to input, store, access, process and analyse data.

🔒2. Security

Strong encryption and tokenization protect data throughout its lifecycle. Only authorised people can decrypt and view sensitive data → organisations stay in control and compliant.

🔎3. Indexing / Searching

An index is a data structure that speeds up data retrieval (mainly SELECT queries), at the cost of extra writes and storage space — but faster search is worth it.

📈4. Scalability

Storage and processing capacity of an RDBMS can be scaled up by increasing the horsepower of the server (more processor power, primary & secondary storage).

🔁5. Transaction processing — ACID properties

RDBMS supports the ACID properties of a transaction (a transaction = a unit of work, e.g., transferring money):

A · Atomicity

All or nothing — a transaction happens in its entirety or not at all.

C · Consistency

DB moves from one consistent state to another. Same data stored in 2+ places must agree.

I · Isolation

Each transaction runs as if it were the only transaction happening.

D · Durability

Once done, changes are permanent (survive crashes).

🧠 Memory trick — 5 eases of structured data
"I S I S T" → Insert/update/delete · Security · Indexing · Scalability · Transaction processing (ACID).
📌 ACID with a bank example
You send ₹500 to a friend. Atomicity: money leaves your account and reaches theirs — never only one. Consistency: total money in the bank is still correct. Isolation: another transfer at the same moment doesn't mix with yours. Durability: after "Success", a power cut won't undo it.

1.4Semi-structured data@@s1-4@@

Definition

Semi-structured data is data which does not conform to a data model but has some structure. It is not in a form which can be used easily by a computer program. It is also called a self-describing structure.

Examples: emails, XML, markup languages like HTML, JSON.

Features of semi-structured data (5 points)

  1. It does not conform to the data models associated with relational databases or any other form of data tables.
  2. It uses tags to segregate semantic elements.
  3. Tags are also used to enforce hierarchies of records and fields within data.
  4. There is no separation between the data and the schema. The amount of structure used depends on the purpose at hand.
  5. Entities of the same class grouped together need not have the same set of attributes. Even if they do, the order of attributes may differ — and it doesn't matter.

Characteristics of semi-structured data

🔀 Inconsistent structure

Records may look different from each other.

🏷 Self-describing

Uses label/value pairs (e.g., "name": "Asha").

🧩 Schema blended with data

Schema information is often mixed into the data values.

❓ Unknown attributes

Data objects may have different attributes not known beforehand.

Sources of semi-structured data

The front runners are XML and JSON (plus other markup languages like HTML).

  1. XML — eXtensible Markup Language: hugely popularised by web services built on the SOAP (Simple Object Access Protocol) principles.
  2. JSON — JavaScript Object Notation: used to transmit data between a server and a web application. Popularised by web services built on REST (Representational State Transfer). MongoDB and Couchbase (originally Membase) — open-source, distributed, NoSQL, document-oriented databases — store data natively in JSON.
  3. Other markup languages — e.g., HTML.
⚠️ Don't mix up

💡 Why is an email "semi-structured"?
Its header has fixed labelled fields (To, From, Subject, Date) → some structure. But its body is free text → unstructured. So an email as a whole is semi-structured, while the body of an email is listed as unstructured.

1.5Unstructured data@@s1-5@@

Definition

Unstructured data is data which does not conform to a data model or is not in a form which can be used easily by a computer program. About 80–90% of an organisation's data is in this format.

Examples: memos, chat rooms, PowerPoint presentations, images, videos, letters, research papers, white papers, body of an email.

Characteristics

  • Un-organised data
  • No predefined data model (non-relational)
  • 80% of enterprise data is unstructured (Source: Gartner)
  • Can never be stored in databases' tables, rows and columns
  • Difficult to search
  • Storing AADHAR images of users is unstructured data
  • Examples: social media data, images, videos, CCTV data, etc.

Issues with terminology

Calling data "unstructured" isn't always perfect. Three issues:

  1. Structure can be implied despite not being formally defined.
  2. Data with some structure may still be labelled unstructured if the structure doesn't help with the processing task at hand.
  3. Data may have some structure or may even be highly structured in ways that are unanticipated or unannounced.

1.6Dealing with unstructured data@@s1-6@@

How do we find patterns in or interpret unstructured data? The textbook lists these techniques:

Figure 1.4 — Techniques to find patterns in / interpret unstructured data
🧠 Memory trick — 7 techniques
"Dark Tea Never Needs More Pure Upgrades" → Data mining · Text analytics · NLP · Noisy text analytics · Manual tagging with metadata · POS tagging · UIMA.
⛏1. Data Mining

Finding useful patterns or information from a large amount of data. Also called knowledge discovery in databases (KDD), because we discover useful knowledge from stored data. Uses methods at the intersection of statistics, AI, machine learning and databases.

e.g., a supermarket analyses thousands of bills to find: what products people buy together, which products are popular, how one factor affects another.

Popular algorithms:

  • Association rule mining — relationships between items: customers who buy bread also buy butter (market basket analysis).
  • Regression analysis — predicts one variable from another: predicting marks from study hours.
  • Collaborative filtering — predicts what a person will like based on what similar people like (Netflix/Amazon recommendations).
📝2. Text Analytics / Text Mining

Finding useful information and patterns from text — emails, blogs, social media, messages, reviews.

e.g., analysing 10,000 product reviews → "Most customers are happy, but many complain about battery life."

Text mining includes:

  • Text categorisation → putting text into categories
  • Text clustering → grouping similar text
  • Sentiment analysis → positive / negative / neutral
  • Concept/entity extraction → finding names, places, organisations
💬3. Natural Language Processing (NLP)

Teaching computers to understand human (natural) language.

Examples: Google Translate, chatbots, voice assistants, spam detection, speech-to-text. You type "I am feeling happy today." → NLP helps the computer understand its meaning.
🤪4. Noisy Text Analytics

Noisy text = text with mistakes, abbreviations, slang or unnecessary words — e.g., "hey!!! u coming tmrw??", "I ammmmm sooooo happyyyy". Noisy text analytics extracts useful info from such messy text (chats, SMS, blogs, call-centre notes).

It deals with: spelling mistakes, abbreviations (u = you), slang, missing punctuation, missing letters, unnecessary words like "wru".
🏷5. Manual Tagging with Metadata

Metadata = information about data. Manual tagging = a person manually adds labels/tags so computers can understand and organise the information.

A news article tagged: Sports, Cricket, India, 2026 → easier to organise & search.
🔤6. Part-of-Speech (POS) Tagging

Identifying the grammatical role of each word in a sentence.

"Rahul plays cricket." → Rahul = Noun, plays = Verb, cricket = Noun.
"The beautiful flower grows." → The = Determiner, beautiful = Adjective, flower = Noun, grows = Verb.
🧱7. UIMA — Unstructured Information Management Architecture

An open-source platform originally developed by IBM. Its purpose is to process unstructured data (such as text) and extract useful information from it — used for real-time content analytics.

"Apple launched a new product in California." → Apple = Organisation, California = Location, new product = Concept/entity.

Q1.Why is an email placed in the "unstructured" category?
The body of an email is free-form text with no data model — it can contain anything (sentences, slang, links, attachments, images). It can't be stored in rows and columns or queried easily, so it's unstructured. (Its header — To, From, Date, Subject — does have structure, which is why emails are sometimes called semi-structured.)
Q2.A book is issued from the library. What details can be placed in an RDBMS table?
Book(BookID PK, Title, Author, Publisher, ISBN, Edition, YearOfPublication, Category) · Member(MemberID PK, Name, Department, Phone) · Issue(IssueID PK, BookID FK, MemberID FK, IssueDate, DueDate, ReturnDate, Fine). Constraints: BookID UNIQUE/NOT NULL, DueDate > IssueDate, Fine ≥ 0.
