Apache Spark Overview

The story of this unit MapReduce writes to disk after every step, which is slow. Spark does the same kind of distributed work but keeps data in memory. A Spark program is a driver that plans the work and executors on worker nodes that do it, with a cluster manager handing out machines. Your code becomes a job, split into stages and tasks. Finally: how to install Spark, write a first program and choose a cluster manager.

3.1What Spark is and its components@@c1@@

Definition

Apache Spark is an open-source cluster computing framework for data analytics, designed for quick computation. It supports in-memory cluster computing and parallel processing, and is faster than Hadoop.

  • A tool for processing large datasets quickly, on one computer or many.
  • APIs for Scala, Java, Python (and SQL, R). Your lab uses PySpark on one Ubuntu machine.
  • Up to 100× faster than MapReduce in memory (~10× on disk). Started at UC Berkeley's AMPLab (2009, Matei Zaharia); Apache top-level project 2014.

3.2Terminology: SparkContext, job, stage, task@@c2@@

SparkContext

The entry point of a Spark application. It connects to the Spark execution environment and is used to create RDDs, accumulators and broadcast variables, access Spark services and run jobs.

Responsibilities of SparkContext
  1. Check the current status of the application
  2. Cancel a job or stage
  3. Run a job synchronously or asynchronously
  4. Access or unpersist a cached RDD
  5. Dynamic allocation of resources

From Spark 2.0, SparkSession wraps SparkContext as the single entry point.

Spark Shell — a Scala command line with auto-completion, for trying Spark before writing an application (pyspark for Python).

Spark application — a self-contained computation running user code; its processes can stay alive even when no job is running.

🧠 Memory trick
"Spark Can Run Any Data" — Status, Cancel, Run, Access, Dynamic.
  • Task — the smallest unit of work, sent to one executor; one task per data partition.
  • Job — a parallel computation of many tasks, created when an action (e.g., count()) runs.
  • Stage — a set of tasks that depend on each other; a job is split into stages where some steps must wait for others (a shuffle).
{{fig:u3_jst|One action → one job → stages → tasks}}
⚠️ Trap
A Hadoop job = one map + one reduce. A Spark job can have many stages, so it can do the work of several chained MapReduce jobs. Order of size: Application ⊃ Job ⊃ Stage ⊃ Task ("All Jobs Split into Tasks").

3.3Spark architecture@@c3@@

🗣 In plain words
A restaurant: the driver is the head chef who reads the order and plans; executors are the cooks; the cluster manager is the manager who gives each chef cooks and stoves; a task is one dish.

Like Hadoop, Spark uses a master–slave architecture: one master and many slaves. The driver is the central coordinator. The driver and each executor run in their own Java process. A Spark application = a driver and its executors. Spark has its own standalone cluster manager and also works with YARN and Mesos.

{{fig:u3_arch|✏️ must-draw · Apache Spark architecture}}
PartRole
Driver programRuns the main() function and creates the SparkContext; does job scheduling and negotiates with the cluster manager; stores RDD information. Runs in client or cluster mode; prepares user code and ships it (as JAR or Python files) to executors.
Cluster managerAllocates resources across applications — Hadoop YARN, Apache Mesos, Standalone scheduler. Standalone makes it easy to set up Spark on an empty set of machines.
Worker nodeA slave node that runs application code.
ExecutorA process launched for an application on a worker node: runs tasks, keeps data in memory/disk (cache), reads and writes external data. Every application has its own executors.
TaskA unit of work sent to one executor.
⚠️ Trap
The cluster manager only hands out resources — it does not schedule tasks or run your code. The driver schedules tasks.

3.4How a Spark job executes@@c4@@

{{fig:u3_exec|✏️ must-draw · Internals of job execution}}
  1. The driver creates a SparkSession/SparkContext and defines operations (read → filter → map) — nothing runs yet.
  2. When an action (e.g., count()) appears, a job is created.
  3. The DAG Scheduler builds the graph of operations (DAG = directed acyclic graph, arrows only go forward) and splits it into stages.
  4. The Task Scheduler launches the tasks through the cluster manager.
  5. The cluster manager allocates resources and tracks the job; the code (JARs) goes to executors on worker nodes, which run the tasks.

Run-time architecture — 10 steps

{{fig:u3_runtime|Run-time flow of a Spark application}}
  1. Driver negotiates resources with the cluster manager.
  2. Cluster manager launches executors for the driver.
  3. Executors register with the driver.
  4. Code is converted into a logical DAG.
  5. The DAG is optimised.
  6. It becomes a physical execution plan with stages.
  7. Small units called tasks are sent to the cluster.
  8. Executors execute the tasks; the driver monitors them.
  9. The driver schedules future tasks by tracking where cached data is.
  10. stop() on SparkContext terminates the executors and releases resources.
🧠 Memory trick
"New Labourers Report; the boss Lists, Organises, Plans, gives Tasks; they Execute, he Monitors, then Says stop." Same shape as YARN: ask for resources → start workers → run → monitor → release (the driver plays the ApplicationMaster's role).

3.5Installing and running Spark, cluster managers@@c5@@

Your slides list these topics in the agenda; the details below are from the textbook.

Installing on Ubuntu: (1) install Java (JDK) → (2) download the pre-built Spark .tgz → (3) extract with tar -xzf and move to /opt/spark → (4) set SPARK_HOME and add bin/sbin to PATH → (5) verify with pyspark or spark-shell --version. (Python-only shortcut: pip install pyspark.) Folders: bin (shells, spark-submit, run-example), sbin (start-master/worker), conf, examples, jars, data. Shells: spark-shell (Scala), pyspark, sparkR, spark-sql — sc and spark are ready-made. Web UI: localhost:4040.

First program (shell) 
>>> lines = sc.textFile("README.md")
>>> lines.count()       # action → job
>>> lines.first()
>>> lines.filter(lambda l: "Spark" in l).count()
Word count app 
counts = (sc.textFile("input.txt")
  .flatMap(lambda l: l.split())
  .map(lambda w: (w, 1))          # like a mapper
  .reduceByKey(lambda a, b: a+b)) # like a reducer
print(counts.collect()); spark.stop()
$ spark-submit --master local[4] wc.py

spark-submit runs an application; main options: --master (where to run), --deploy-mode (client/cluster), --class (Java/Scala main class), executor memory/cores.
