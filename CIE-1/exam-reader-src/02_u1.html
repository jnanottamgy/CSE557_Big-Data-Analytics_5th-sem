Unit 1

Big Data & Big Data Analytics

The story of this unit Data comes in three shapes. Most of it is messy (unstructured). There is now so much, arriving so fast, in so many shapes, that we call it Big Data. Analysing it — Big Data Analytics — gives businesses better decisions. Doing that needs data scientists and special architectures (many machines, sharing nothing), which run into the CAP trade-off.
Textbook: Seema Acharya & Subhashini Chellappan

1.1Data and its three types@@a1@@

🗣 In plain words
Data = raw facts a computer can store and work on. Organise it and it becomes information; understand it and it gives insights.
Definition — data

The quantities, characters or symbols on which operations are performed by a computer, which may be stored and transmitted as electrical signals and recorded on magnetic, optical or mechanical recording media.

  • Quantitative (numbers) — discrete = counted (20 dogs), continuous = measured (18 cm). Qualitative = descriptive (red, soft).
  • Data sits inside the enterprise and outside its firewall, in homogeneous (same kind) and heterogeneous (mixed) sources.
  • Computer data = text, images, audio, programs… processed by the CPU, stored in files/folders.
{{fig:u1_dtypes|Types of data}}

Digital data comes in three types. Think of three cupboards: labelled boxes in neat rows (structured), items with name-tags but no fixed boxes (semi-structured), and a pile (unstructured).

{{fig:u1_three|✏️ must-draw · Classification of digital data and their share of enterprise data}}
🔑 Key point
80–90% of an organisation's data is unstructured (Gartner: 80%). That is why ordinary databases are not enough and Big Data tools exist.

1.2Structured data@@a2@@

Definition

Data in an organised form (rows and columns) that can be easily used by a computer program; relationships exist between entities (like classes and objects). Example: data stored in databases.

  • Lives mostly in an RDBMS (Oracle, MySQL, SQL Server, DB2, Teradata, PostgreSQL; also MS Access, Excel, OLTP systems).
  • A table = a relation. Cardinality = number of rows; degree = number of columns.
  • Designing it: (1) choose columns and data types; (2) add constraints — UNIQUE, NOT NULL, business rules (e.g., value ≥ 50), permissible values (e.g., only CS/IS/MS); (3) relate tables through a common column (primary key ↔ foreign key).
📌 Example — Employee table
EmpNo (primary key), EmpName, Designation (NOT NULL), DeptNo, ContactNo (NOT NULL). Rows: E101 Allen, E102 Simon → cardinality 2, degree 5. It links to a Department table through DeptNo.
{{fig:u1_tables|Tables related through a common column}}

1.3Semi-structured and unstructured data@@a3@@

Semi-structured data

Definition

Data that does not conform to a data model but has some structure; not easily used by a program. Also called a self-describing structure. Examples: emails, XML, HTML, JSON.

5 features
  1. Doesn't follow the relational data model.
  2. Uses tags to separate meaning (semantic elements).
  3. Tags also build hierarchies of records and fields.
  4. No separation between data and schema.
  5. Entities of the same class can have different attributes, in any order.
4 characteristics
  1. Inconsistent structure.
  2. Self-describing — label/value pairs.
  3. Schema information blended with data.
  4. Attributes may not be known beforehand.

Sources: XML (popularised by SOAP web services), JSON (sends data between server and web app; popularised by REST; MongoDB and Couchbase/CouchDB store JSON natively), HTML.

📌 Self-describing JSON
{ _id: 9, BookTitle: "Fundamentals of Business Analytics", AuthorName: "Seema Acharya", Publisher: "Wiley India" } — each value carries its own label. An email is semi-structured: the header (To, From, Subject) has fields, the body is free text.

Unstructured data

Definition

Data that does not conform to a data model or is not in a form easily used by a computer program. 80–90% of organisational data. Examples: memos, chat rooms, PPTs, images, videos, letters, research papers, body of an email.

It is un-organised, has no predefined model, cannot be stored in rows and columns, and is hard to search (e.g., storing users' Aadhaar images, CCTV footage, social media posts).

{{fig:u1_unstr|Unstructured data is machine-generated or human-generated}}

Why "unstructured" is an imperfect label (3 issues): structure may be implied but not formally defined · data may have structure that doesn't help the task at hand · data may have structure that is unexpected or unannounced.

1.4What Big Data is@@a4@@

Characteristics of any data — the 3 Cs:

  • Composition — its structure: sources, granularity, types, static or real-time streaming.
  • Condition — its state: usable as is, or needs cleansing?
  • Context — where and why it was generated.
{{fig:u1_3c|The 3 Cs of data}}
{{fig:u1_evol|Evolution of Big Data: mainframes → RDBMS → WWW & IoT}}

Data went from primitive and structured (mainframes, ≤1970s) to complex and relational (RDBMS, 1980s–90s) to complex and unstructured (web, IoT, social media, 2000s+). The web and IoT caused the explosion we call Big Data.

Gartner definition — learn word-for-word

"Big Data is high-volume, high-velocity and high-variety information assets that demand cost-effective, innovative forms of information processing for enhanced insight and decision making."

Three parts: what it is (3 Vs) → what it needs (new processing) → what it gives (insight, decisions). Chain: data → information → actionable intelligence → better decisions → enhanced business value. Informal views from the slides: "anything beyond our infrastructure", "today's BIG is tomorrow's NORMAL", "TB, PB, ZB of data", "the 3 Vs".

The 3 Vs

{{fig:u1_3v|✏️ must-draw · Big in volume, velocity and variety}}
  • Volume — how much. KB → MB → GB → TB → PB → EB → ZB → YB, each ×1024 (≈ ×1000).
  • Velocity — how fast. Batch → periodic → near real time → real time (e.g., card-fraud check at swipe).
  • Variety — how many kinds. Structured + semi-structured + unstructured.
🧠 Memory trick
A river: how much water (volume), how fast (velocity), how many things floating in it (variety). Units: "Kind Men Give Tea, Please Eat Zesty Yogurt".
{{fig:u1_sources|Where the volume comes from: internal, external and both}}

Other characteristics (not part of the definition): Veracity — can we trust it (noise, bias)? and Validity — is it correct for this problem? · Volatility — how long it stays useful (stock price today vs birth date) · Variability — the flow is irregular, with sudden peaks (festival-sale traffic).

⚠️ Trap
Velocity (speed of arrival) ≠ Variability (irregular flow) ≠ Volatility (how long it stays valid).

1.5Challenges, why Big Data, and BI vs Big Data@@a5@@

Challenges with Big Data (6):

  1. Huge growth — hard to tell useful data from noise.
  2. Cloud computing & virtualisation — cheap, flexible infrastructure, but deciding what to host where.
  3. Data retention — how long to keep data.
  4. Lack of skilled professionals.
  5. Capture, storage, processing & security — traditional databases can't cope with data that is large, fast and varied.
  6. Visualisation — showing it with charts/dashboards; shortage of experts.

1.7Data science and the data scientist@@a7@@

Definition

Data science is the science of extracting knowledge from data — finding hidden patterns using mathematics, statistics, IT, machine learning, data engineering, probability models and pattern recognition.

Used in weather prediction, oil drilling, seismic activity, financial fraud, social media analytics, retail & manufacturing (churn, market-basket analysis). Process: collect → prepare → analyse → visualise → communicate → decide.

{{fig:u1_venn|Three skill sets of a data scientist}}
  • Business acumen — domain knowledge, business strategy, problem solving (turn a business question into a data question), communication, presentation, inquisitiveness.
  • Technology — RDBMS, NoSQL (MongoDB, Cassandra, HBase), programming (Python, Java), data warehousing, data mining, visualisation (Tableau).
  • Mathematics — maths, statistics, algorithms, machine learning, pattern recognition, NLP.
🧠 Memory trick
BTM — a three-legged stool: remove one leg and it falls.
{{fig:u1_ds|The data scientist's 4 responsibilities}}
  1. Data management — raw → clean (fix errors, remove duplicates, fill missing) → integrate → ready dataset.
  2. Analytical techniques — models and algorithms to find relationships, trends and patterns, chosen to fit the question.
  3. Business / domain expertise — "attendance and marks are related" becomes "low-attendance students need early mentoring".
  4. Communication & presentation — turn hundreds of numbers into a chart and a clear message.

Data science is a field; a data scientist is a person who applies it. Careers: data analyst, data scientist, ML engineer, data engineer, BI professional, AI/NLP/vision roles.

1.8Terminologies used in Big Data environments@@a8@@

In-memory analytics & in-database processing

Reading from a hard disk is slow. Pre-computing cubes or aggregate tables helps, but you must guess in advance what you will need. In-memory analytics keeps all relevant data in RAM, so nothing has to be fetched from disk. Advantages: faster access, rapid deployment, better insights, minimal IT involvement.

{{fig:u1_inmem|Disk vs in-memory}}

In-database processing (in-database analytics): normally OLTP data is cleaned through ETL into an Enterprise Data Warehouse, then exported to a separate analytics program. In-database processing runs the computation inside the database itself — no export, saving time.

💡 The pair
In-memory brings data closer to the CPU; in-database brings computation to where the data lives. Both cut data movement.

🧠 Memory trick
SMP = "Same Memory, Please"; MPP = "My Private Partition".

Parallel vs distributed systems

{{fig:u1_par|Parallel system}} {{fig:u1_dist|Distributed system}}

Parallel: tightly coupled; processors cooperate on the same query; user is unaware of the parallelism; shared memory or message passing. Distributed: loosely coupled separate machines on a network; each runs its own applications and serves its own users; data spread across machines, so a query may touch several.

Shared nothing architecture

{{fig:u1_snsd|✏️ must-draw · Shared memory, shared disk, shared nothing}}

Three multiprocessor architectures: shared memory (common memory), shared disk (private memory, common disks), shared nothing (neither memory nor disk shared; nodes talk over the network). Advantages of shared nothing:

  • Fault isolation — a fault in one node stays in that node, visible only through messages (or their absence).
  • Scalability — with a shared disk, nodes must take turns (synchronisation), which limits how many can be added; with nothing shared there is no central bottleneck. Hadoop uses shared nothing.

1.9CAP theorem@@a9@@

Definition

Also called Brewer's theorem: in a distributed system it is impossible to guarantee Consistency, Availability and Partition tolerance all at once — at best you get two of the three.

  • Consistency — every read gets the latest write.
  • Availability — every request gets a response from a non-failing node in reasonable time.
  • Partition tolerance — the system keeps working when the network breaks between nodes.

Network breaks will happen, so P is usually required; the real choice during a partition is C vs A.

PairExamples
CATraditional RDBMS — MySQL, PostgreSQL
CPHBase, MongoDB, Redis, MemcacheDB, BigTable
APRiak, Cassandra, CouchDB, Dynamo
{{fig:u1_cap|✏️ must-draw · CAP triangle with databases}}
{{fig:u1_capstory|The training-schedule story: two administrators give different answers = inconsistent}}

Choose consistency when stale data is dangerous (bank balance) — some requests wait. Choose availability when the service must keep answering and small differences can be fixed later (social feeds, caches).

🧠 Memory trick
CP = "Correct Please": "Happy Monkeys Run Many Bananas". AP = "Always Present": "Real Cats Chase Dogs". CA = classic RDBMS.
