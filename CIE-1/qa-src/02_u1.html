Q1.Define Big Data.2M

According to Gartner, "Big Data is high-volume, high-velocity and high-variety information assets that demand cost-effective, innovative forms of information processing for enhanced insight and decision making." In short, it is data that is big in volume, velocity and variety — beyond what traditional systems can store and process.

Q2.Why is an email placed in the "unstructured" category?★ from slides2M

The body of an email is free-form text that follows no data model — it can contain sentences, slang, links, images and attachments in any order — so it cannot be stored in rows and columns or queried easily by a program. Hence it is unstructured. (Only its header — To, From, Date, Subject — has some structure, which is why email is sometimes called semi-structured.)

Q3.What is semi-structured data? Give two examples.2M

Semi-structured data does not conform to a data model but has some structure; it uses tags / label–value pairs to separate elements, so it is called self-describing. Examples: XML (used by SOAP web services) and JSON (used by REST services, stored natively by MongoDB). HTML and emails are other examples.

Q4.Expand and explain ACID.2M

ACID are the properties of a transaction supported by an RDBMS: Atomicity — the transaction happens fully or not at all; Consistency — the database moves from one valid state to another; Isolation — each transaction runs as if it were the only one; Durability — once committed, changes are permanent even after a crash.

Q5.Differentiate veracity, volatility and variability.2M

Veracity — trustworthiness of data (noise, bias, abnormality); Volatility — how long data remains valid and useful (decides storage duration); Variability — data flow is inconsistent, with sudden peaks the system must handle. These are characteristics of data that are not definitional traits of Big Data.

Q6.State the CAP theorem.2M

The CAP (Brewer's) theorem states that in a distributed system it is impossible to provide Consistency, Availability and Partition tolerance at the same time — at most two can be guaranteed. Consistency: every read gets the latest write; Availability: every request gets a response; Partition tolerance: the system works despite network failures.

Q7.Explain the 3 Vs of Big Data.3M
  1. Volume — the huge amount of data, growing from GB/TB to PB, EB and ZB, coming from internal sources (databases, archives) and external ones (web, social media, sensors).
  2. Velocity — the speed at which data is generated and processed: batch → periodic → near real time → real time (e.g., fraud check at card swipe).
  3. Variety — the many types of data: structured (RDBMS), semi-structured (XML, JSON) and unstructured (text, images, audio, video).

Structured details go into related tables:

Q11.What is a shared nothing architecture? State its advantages.3M

Of the three multiprocessor architectures — shared memory, shared disk and shared nothing — shared nothing is the one where neither memory nor disk is shared: each node has its own processor, memory and disk and communicates over the network (Hadoop uses it). Advantages:

  1. Fault isolation — a fault in one node is confined to that node and exposed only through messages (or their absence).
  2. Scalability — with a shared disk, nodes must synchronise and take turns, which limits how many can be added; with nothing shared there is no central bottleneck, so nodes can be added freely.
Q12.Explain any three challenges with Big Data.3M
  1. Huge growth of data — data grows exponentially, making it hard to separate useful data from noise.
  2. Data retention — deciding how long to store data; some stays useful for long-term decisions, some becomes irrelevant quickly.
  3. Capture, storage, processing & security — traditional databases cannot capture, store, search, transfer and secure data that is very large, fast and varied.

Others you may write: cloud computing & virtualisation · lack of skilled professionals · data visualisation.

Q13.List and explain the classification of digital data with examples.★ from slides5M

Digital data is classified into three types:

{{fig:u1_three|Classification of digital data}}
  1. Structured data — data in an organised form (rows and columns) that is easily used by a program; relationships exist between entities. Stored in RDBMS (Oracle, MySQL, SQL Server, DB2), MS Excel, MS Access. Easy to insert/update/delete, secure, indexed, scalable and supports ACID transactions. Example: an Employee table (EmpNo, Name, DeptNo).
  2. Semi-structured data — does not conform to a data model but has some structure; uses tags to separate semantic elements and build hierarchies; no separation of data and schema; self-describing. Examples: XML, JSON, HTML, email.
  3. Unstructured data — does not conform to any data model and cannot be easily used by a program; 80–90% of an organisation's data. Machine-generated (satellite images, CCTV, radar) or human-generated (emails, documents, chats, social media). Examples: images, videos, audio, memos, body of an email.

Comparison: moving from structured → semi-structured → unstructured, flexibility and scalability increase, while robustness, transaction support and query power decrease.

Q14.Explain the techniques used to find patterns in or interpret unstructured data.★ from slides5M
{{fig:u1_tech|Techniques for dealing with unstructured data}}
  1. Data mining — discovering useful patterns in large data ("knowledge discovery in databases"), using statistics, AI, ML and databases. Algorithms: association rule mining (bread buyers also buy butter), regression (predict marks from study hours), collaborative filtering (recommend what similar people like).
  2. Text analytics / text mining — patterns from text such as emails, blogs and reviews: text categorisation, clustering, sentiment analysis, concept/entity extraction.
  3. Natural Language Processing (NLP) — enabling computers to understand human language (translation, chatbots, spam detection).
  4. Noisy text analytics — extracting information from messy text with spelling mistakes, abbreviations and slang ("u coming tmrw??") — chats, SMS, call-centre notes.
  5. Manual tagging with metadata — a person adds tags (data about data) so the content can be organised and searched (Sports, Cricket, India).
  6. Part-of-speech (POS) tagging — marking the grammatical role of each word ("Rahul–noun plays–verb cricket–noun").
  7. UIMA (Unstructured Information Management Architecture) — an open-source platform by IBM for real-time content analytics; identifies entities such as organisations and locations.

Q15.What is Big Data Analytics? Explain with a neat diagram.5M

Big Data Analytics is the process of examining large and varied data to uncover patterns, trends and insights that help an organisation make better and faster decisions (large data → analyse → patterns → decisions). Example: Amazon analyses past purchases and browsing history to recommend products.

{{fig:u1_bda|What is Big Data Analytics?}}
  1. Technology-enabled analytics — tools from IBM, Tableau, SAS, R and WPS process huge data.
  2. Richer, deeper insights — into customers, partners and operations: what customers buy and what else can be sold to them.
  3. Competitive edge — quicker, better decisions than competitors.
  4. A tight handshake between three communities — IT (infrastructure), data scientists (analysis) and business users (decisions).
  5. Working with datasets whose volume and variety exceed traditional databases.
  6. Moving code to data — the small program is sent to where the huge data is stored, instead of moving terabytes to the program; also time-sensitive decisions in near real time.

Q17.Explain the CAP theorem with an example.5M

The CAP theorem (Brewer's theorem) states that in a distributed computing environment it is impossible to provide all three guarantees — Consistency, Availability and Partition tolerance — simultaneously; at best two can be achieved.

  • Consistency — every read fetches the last write.
  • Availability — reads and writes always succeed; every non-failing node responds in reasonable time.
  • Partition tolerance — the system keeps functioning when a network partition occurs.

Example: a coordinator updates your 3:00 PM training with administrator Raju. You ask administrator Rahul, whose copy wasn't updated: "no training". Two answers for the same data = inconsistent. Forcing them to sync before every reply makes users wait (less available); if they can't talk at all, the system must still work (partition tolerance).

{{fig:u1_cap|Databases and CAP}}

Combinations: CA — traditional RDBMS (MySQL, PostgreSQL) · CP — HBase, MongoDB, Redis, MemcacheDB, BigTable · AP — Riak, Cassandra, CouchDB, Dynamo. Choose C for bank balances, A for social feeds.

Q18.What is data science? Explain the skills and responsibilities of a data scientist.5M

Data science is the science of extracting knowledge from data — finding hidden patterns using mathematics, statistics, IT, machine learning and pattern recognition. A data scientist is the person who applies it to solve real-world problems.

{{fig:u1_venn|A data scientist combines three skill sets}}

Skills:

  • Business acumen — domain understanding, business strategy, problem solving, communication, presentation, inquisitiveness.
  • Technology expertise — RDBMS, NoSQL, programming (Python, Java), data warehousing, data mining, visualisation tools.
  • Mathematics expertise — statistics, algorithms, machine learning, pattern recognition, NLP.

Responsibilities:

  1. Data management — prepare and integrate large, varied datasets (clean errors, remove duplicates, handle missing values).
  2. Analytical techniques — apply models and algorithms to find relationships, trends and patterns.
  3. Business / domain expertise — give results real-world context ("low attendance → early mentoring").
  4. Communication & presentation — explain findings clearly to stakeholders through charts and simple language.
