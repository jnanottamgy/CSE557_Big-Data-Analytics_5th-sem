Q37.What is Apache Spark?2M

Apache Spark is an open-source cluster computing framework for data analytics, designed for quick computation. It supports in-memory cluster computing and parallel processing, runs on one or many computers, provides APIs in Scala, Java and Python, and is much faster than Hadoop MapReduce (up to 100× in memory).

Q38.What is SparkContext?2M

SparkContext is the entry point of a Spark application. It connects to the Spark execution environment and is used to create RDDs, accumulators and broadcast variables, access Spark services and run jobs. It is created by the driver program (from Spark 2.0 it is wrapped by SparkSession).

Q39.What is an executor in Spark?2M

An executor is a process launched for an application on a worker node. It runs the tasks sent by the driver, keeps data in memory or disk storage (cache) across them, and reads/writes data to external sources. Every Spark application has its own executors, each running as a separate Java process.

Q40.What is the Spark Shell?2M

The Spark Shell is a Spark application written in Scala that provides an interactive command-line environment with auto-completion. It is used to explore Spark's features before writing a standalone application; sc (SparkContext) is created automatically. The Python equivalent is pyspark.

Q41.List the cluster managers supported by Spark.2M

A cluster manager allocates resources across applications. Spark supports: Standalone (Spark's own cluster manager), Hadoop YARN, Apache Mesos, and Kubernetes (Spark 2.3+); local mode runs everything on a single machine for testing.

Q42.Differentiate client mode and cluster mode.2M

In client mode the driver runs on the machine that submits the application — used for interactive work and shells; closing the terminal stops the app. In cluster mode the driver runs inside the cluster (on YARN, inside the ApplicationMaster) — used for production; the client can disconnect.

Q43.Define task, job and stage in Spark.3M
  1. Task — the smallest unit of work, sent to a single executor; each partition of an RDD gets its own task.
  2. Job — a parallel computation made up of multiple tasks, created in response to an action such as count() or collect().
  3. Stage — a set of tasks within a job that depend on each other; a job is split into stages because some steps must wait for others to finish (e.g., a shuffle).

Application ⊃ Job ⊃ Stage ⊃ Task.

Q44.List the responsibilities of SparkContext.3M

SparkContext, the entry point of a Spark application, is responsible for:

  1. Checking the current status of the Spark application.
  2. Cancelling a job or a stage.
  3. Running a job synchronously or asynchronously.
  4. Accessing or unpersisting a cached RDD.
  5. Programmable dynamic allocation of resources.

Q46.Explain the role of the driver program.3M
  1. The driver is a process that runs the main() function of the application and creates the SparkContext; it is the central coordinator of the master–slave architecture.
  2. It handles job scheduling and negotiation with the cluster manager, and stores RDD information; it converts code into a DAG, stages and tasks and sends tasks to executors.
  3. It can run in client or cluster mode; it prepares the user code and ships the application (JAR or Python files) to the executors, then monitors them until stop().
Q47.Explain the internal (master–slave) working of Spark.3M
  1. Like Hadoop, Spark uses a master–slave architecture with one master and many slaves; the driver is the central coordinator.
  2. The driver and each executor run in their own Java process; one driver handles a large number of executors.
  3. A Spark application is a collaboration of the driver and its executors. Resources come from Spark's own standalone cluster manager or from open-source managers like YARN and Mesos.
Q48.What is a DAG? Explain the roles of the DAG Scheduler and the Task Scheduler.3M
  1. A DAG (Directed Acyclic Graph) is a graph of operations whose arrows only move forward (no loops); Spark records a program's operations as a DAG and optimises it before running.
  2. When an action creates a job, the DAG Scheduler builds the operator DAG and splits it into stages of tasks, submitting each stage when it is ready.
  3. The Task Scheduler launches the tasks via the cluster manager onto executors on the worker nodes.

Q49.Explain the Apache Spark architecture with a neat diagram.5M

Spark follows a master–slave architecture: one driver (central coordinator) and many executors, with a cluster manager allocating resources. A Spark application is the collaboration of a driver and its executors, each running in its own Java process.

{{fig:u3_arch|Apache Spark architecture overview}}
  1. Driver program — runs the main() function and creates the SparkContext; performs job scheduling, negotiates with the cluster manager, stores RDD information; converts code into tasks; runs in client or cluster mode.
  2. SparkContext — the entry point that connects the driver to the cluster and coordinates the application.
  3. Cluster manager — acquires/allocates resources from the cluster across applications: Standalone, Hadoop YARN or Apache Mesos.
  4. Worker node — a slave node that runs application code.
  5. Executor — a process on a worker node that performs all data processing (runs tasks) and stores results in memory (cache); reads/writes external data.
  6. Task — a unit of work sent by the driver to one executor.

Q50.Explain the components of Apache Spark.5M
{{fig:u3_stack|Apache Spark components}}
  1. Spark Core — the foundation everything else runs on; provides the execution platform for every Spark application (task scheduling, memory management, fault recovery, interaction with storage) and APIs in R, SQL, Python, Scala and Java.
  2. Spark SQL — runs SQL and HiveQL queries on structured and semi-structured data, often faster than older systems; provides DataFrames.
  3. Spark Streaming — processes live data by breaking it into small micro-batches that run on Spark Core (e.g., live logs, tweets).
  4. MLlib — Spark's machine learning library, built to use in-memory processing for iterative algorithms.
  5. GraphX — a graph computation engine for graph-structured data at scale.
  6. SparkR — a lightweight front end for R users to analyse large datasets interactively from the R shell.

All of these run on a cluster manager (Standalone, YARN, Mesos).

Q51.Explain the run-time architecture of a Spark application.5M
{{fig:u3_exec|Internals of job execution in Spark}}
  1. The driver talks to the cluster manager and negotiates for resources.
  2. The cluster manager launches executors on behalf of the driver.
  3. The executors register themselves with the driver.
  4. When a job enters (an action is called), the driver converts the code into a logical DAG.
  5. The DAG is optimised.
  6. It is converted into a physical execution plan with a set of stages (DAG Scheduler).
  7. Small execution units called tasks are created and sent to the cluster (Task Scheduler).
  8. Executors execute all the tasks assigned by the driver, while the driver monitors them.
  9. The driver schedules future tasks by tracking the location of cached data (data placement).
  10. When stop() is called on SparkContext, it terminates all executors and releases the resources from the cluster manager.

Q52.Explain the different cluster manager types in Spark.5M

The cluster manager allocates resources (CPU, memory) across Spark applications by launching executors; it does not schedule tasks. It is chosen with --master in spark-submit.

{{fig:u3_cm|Cluster manager types}}
  1. Standalone — Spark's own simple cluster manager, shipped with Spark; easy to set up a cluster on an empty set of machines (one master + workers). spark://HOST:7077.
  2. Hadoop YARN — the resource manager of Hadoop 2; runs Spark on an existing Hadoop cluster, sharing resources and reading HDFS; executors run in YARN containers. --master yarn.
  3. Apache Mesos — a general-purpose cluster manager that can run Spark alongside other frameworks. mesos://HOST:5050.
  4. Kubernetes — runs the driver and executors as pods (Spark 2.3+). k8s://….
  5. Local mode — no cluster; everything on one machine using local, local[K] or local[*] threads — for learning and testing.

Deploy modes: client (driver on the submitting machine) vs cluster (driver inside the cluster).

Q53.Explain the steps to install Apache Spark and write your first Spark program.5M

Installation (Ubuntu):

  1. Install Java (JDK) and Python 3: sudo apt install openjdk-11-jdk python3.
  2. Download a pre-built Spark package (spark-x.y.z-bin-hadoop3.tgz) from spark.apache.org.
  3. Extract it (tar -xzf …) and move it to /opt/spark.
  4. Set environment variables in ~/.bashrc: SPARK_HOME=/opt/spark, add $SPARK_HOME/bin and sbin to PATH.
  5. Verify: run spark-shell --version or pyspark (Web UI at localhost:4040). Alternatively pip install pyspark.

First Spark program (word count in PySpark):

from pyspark.sql import SparkSession
spark = SparkSession.builder.appName("WordCount").master("local[*]").getOrCreate()
sc = spark.sparkContext
counts = (sc.textFile("input.txt")
            .flatMap(lambda line: line.split())   # split lines into words
            .map(lambda w: (w, 1))                # (word, 1)
            .reduceByKey(lambda a, b: a + b))     # add counts per word
print(counts.collect())                           # action → job runs
spark.stop()

Run it with spark-submit --master local[4] wordcount.py. Shell version: sc.textFile("README.md").count(). Bundled example: ./bin/run-example SparkPi 10 → "Pi is roughly 3.14".
