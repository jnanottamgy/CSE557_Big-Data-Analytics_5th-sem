Spark architecture

What is Spark (U3 §1.1)

Definition

Open-source cluster computing framework for data analytics, designed for quick computation; supports in-memory cluster computing and parallel processing; faster than Hadoop.

  • Processes large datasets quickly on one or many computers; APIs for Scala, Java, Python (+ SQL, R); lab = PySpark on Ubuntu.
  • UC Berkeley AMPLab 2009 (Matei Zaharia); Apache top-level 2014; up to 100× faster in memory, ~10× on disk.

Components (U3 §1.2)

  • Spark Core — foundation / execution platform (APIs: R, SQL, Python, Scala, Java).
  • Spark SQL — SQL & HiveQL on structured/semi-structured data; DataFrames.
  • Spark Streaming — live data as micro-batches.
  • MLlib — machine learning, in-memory for iterative algorithms.
  • GraphX — graph computation.
  • SparkR — R front end from the R shell.

Terminology (U3 §1.3)

  • SparkContext = entry point; connects to the execution environment; creates RDDs, accumulators, broadcast variables; runs jobs. Responsibilities (SCRAD): status · cancel job/stage · run sync/async · access/unpersist cached RDD · dynamic allocation. Spark 2.0+: SparkSession wraps it.
  • Spark Shell — Scala command line with auto-completion. Spark application — self-contained computation running user code.
  • Task = smallest unit, one executor, one per partition · Job = parallel computation of many tasks, triggered by an action · Stage = set of dependent tasks; job split where steps must wait (shuffle). Application ⊃ Job ⊃ Stage ⊃ Task.

Architecture (U3 §1.4–1.5)

  • Master–slave: one driver (central coordinator) + many executors; each its own Java process; app = driver + its executors. Cluster manager: own standalone, or YARN, Mesos.
  • Driver: runs main(), creates SparkContext; job scheduling; negotiates with cluster manager; stores RDD info; client or cluster mode.
  • Executor: process on a worker node; runs tasks; keeps data in memory/disk (cache); reads/writes external data; each app has its own.
  • Cluster manager: allocates resources across apps (YARN, Mesos, Standalone) — does not schedule tasks.
  • Worker node: slave node running app code. Task: unit of work for one executor.

Job execution & run-time flow (U3 §1.6–1.7)

Action → job → DAG Scheduler (builds operator DAG, splits into stages) → Task Scheduler (launches tasks via cluster manager) → executors on worker nodes.

  1. Driver negotiates resources with cluster manager.
  2. Cluster manager launches executors.
  3. Executors register with driver.
  4. Code → logical DAG.
  5. DAG optimised.
  6. Physical plan = set of stages.
  7. Tasks sent to cluster.
  8. Executors execute; driver monitors.
  9. Driver schedules future tasks by cached-data location.
  10. stop() → terminate executors, release resources.

Installation & running

Install on Ubuntu (U3 §2.1)

Java (JDK) → download pre-built .tgz → tar -xzf → move to /opt/spark → set SPARK_HOME, PATH (bin, sbin) → verify pyspark / spark-shell --version. Or pip install pyspark. Folders: bin (shells, spark-submit, run-example), sbin (start-master/worker), conf, examples, jars, data. Shells: spark-shell, pyspark, sparkR, spark-sql (sc, spark ready-made). Web UI localhost:4040.

First program (U3 §2.2)

lines = sc.textFile("README.md")      # RDD
lines.count(); lines.first()          # actions → jobs
lines.filter(lambda l: "Spark" in l).count()
# word count app
counts = (sc.textFile("input.txt")
  .flatMap(lambda l: l.split())
  .map(lambda w: (w, 1))
  .reduceByKey(lambda a, b: a + b))
counts.collect(); spark.stop()
$ spark-submit --master local[4] wordcount.py
