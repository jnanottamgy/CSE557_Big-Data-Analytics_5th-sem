★Cheat sheet@@cheat@@

CHAPTER 1 · Spark architecture

  • Spark = open-source cluster computing framework for data analytics; in-memory cluster computing + parallel processing; faster than Hadoop (up to 100× in memory). APIs: Scala, Java, Python, (SQL, R). Lab: PySpark on Ubuntu.
  • Components: Spark Core (foundation/execution platform) · Spark SQL (SQL & HiveQL on structured/semi-structured data) · Spark Streaming (live data as micro-batches) · MLlib (ML, iterative, in-memory) · GraphX (graphs) · SparkR (R front end).
  • SparkContext = entry point; connects to execution environment; creates RDDs, accumulators, broadcast variables; runs jobs. Responsibilities: status · cancel job/stage · run sync/async · access/unpersist cached RDD · dynamic allocation. (Spark 2: SparkSession wraps it.)
  • Spark Shell = Scala command line with auto-completion. Spark Application = self-contained computation running user code.
  • Task = smallest unit, one executor, one per partition · Job = parallel computation of many tasks, created by an action · Stage = set of dependent tasks; jobs split where steps must wait (shuffle).
  • Master/slave: one driver (central coordinator) + many executors; each is its own Java process; app = driver + its executors. Own standalone cluster manager, or YARN / Mesos.
  • Driver: runs main(), creates SparkContext, job scheduling, negotiates with cluster manager, stores RDD info; client or cluster mode. Executor: process on a worker node; runs tasks; keeps data in memory/disk; reads/writes external data; one set per app. Cluster manager: allocates resources (YARN, Mesos, Standalone). Worker node: slave node running app code. Task: unit of work for one executor.
  • Job execution: action → job → DAG Scheduler (build DAG, split into stages) → Task Scheduler (launch tasks via cluster manager) → executors on worker nodes.
  • Run-time (10): negotiate → launch executors → register → logical DAG → optimise → physical plan (stages) → tasks to cluster → execute (driver monitors) → schedule by cached-data location → stop() kills executors, releases resources.
  • vs MapReduce: in-memory vs disk; DAG vs fixed map/reduce; iterative & streaming; many languages; built-in libraries; no own storage (uses HDFS etc.).

CHAPTER 2 · Installation & running

  • Install: Java (JDK) → download pre-built .tgz → tar -xzf → SPARK_HOME + PATH → pyspark / spark-shell --version. Or pip install pyspark.
  • Folders: bin (shells, spark-submit, run-example) · sbin (start-master/worker) · conf · examples · jars · data.
  • Shells: spark-shell (Scala), pyspark (Python), sparkR, spark-sql. sc & spark ready-made. Web UI at localhost:4040.
  • First program: sc.textFile("README.md") → count(), first(), filter("Spark"). Word count: flatMap → map (w,1) → reduceByKey → collect; spark.stop().
  • spark-submit: --master, --deploy-mode, --class, --name, executor memory/cores.
  • Cluster managers: local (local, local[K], local[*]) · Standalone (spark://HOST:7077, UI 8080) · YARN (yarn) · Mesos (mesos://HOST:5050) · Kubernetes (k8s://…).
  • Deploy modes: client (driver on your machine; shells) vs cluster (driver inside cluster; production).
  • Examples: ./bin/run-example SparkPi 10 → "Pi is roughly 3.14…"; Python: spark-submit examples/src/main/python/pi.py 10.
