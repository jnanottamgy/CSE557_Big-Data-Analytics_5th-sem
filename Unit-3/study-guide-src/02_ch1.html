1.1What is Apache Spark?@@s1-1@@

🗣 In simple words
Spark is a tool for processing large datasets quickly. Like Hadoop MapReduce, it spreads work over many computers — but it keeps data in memory (RAM) between steps instead of writing to disk every time, so it is much faster. It works on one computer or many computers.
Definition

Apache Spark is an open-source cluster computing framework for data analytics, designed for quick computation using a simple cluster technology. It supports in-memory cluster computing and parallel processing, and promises to be faster than Hadoop.

Key features (from your slides)

  • Used for data processing — a tool for processing large datasets quickly.
  • Works on one computer or many computers (a cluster).
  • Supports in-memory cluster computing and parallel processing.
  • Supports various high-level tools for data analysis (SQL, streaming, ML, graphs).
  • Provides APIs for Scala, Java and Python (plus SQL and R).
  • In your course you will use Python (PySpark) on one Ubuntu machine.

A little history from textbook

  • Started in 2009 at UC Berkeley's AMPLab by Matei Zaharia.
  • Open-sourced in 2010; became an Apache top-level project in 2014.
  • Written mainly in Scala; runs on the Java Virtual Machine.
  • Claimed to run programs up to 100× faster than Hadoop MapReduce in memory, and about 10× faster on disk.
Figure 1.1 — Why Spark is faster than Hadoop MapReduce for multi-step work
🔑 Key point
Spark's big idea is in-memory computing. That makes it great for iterative work (machine learning, which loops over the same data many times) and interactive work (asking many quick questions of the same data).

1.2Spark components (the Spark stack)@@s1-2@@

Figure 1.2 — The Spark stack: libraries on top of Spark Core, running on a cluster manager
⚙️ Spark Core

The foundation everything else runs on — provides the execution platform for every Spark application (task scheduling, memory management, fault recovery, talking to storage). Language APIs: R, SQL, Python, Scala, Java.

🗃 Spark SQL

Lets you run SQL and HiveQL queries against structured and semi-structured data, often meaningfully faster than the same queries on older systems. Comes with DataFrames.

🌊 Spark Streaming

Processes live data by breaking it into small micro-batches that run on top of Spark Core. e.g., live tweets, sensor feeds, server logs.

🤖 MLlib

Spark's machine learning library, built to use in-memory processing for iterative algorithms that would otherwise be slow. (Unit 4 topic.)

🕸 GraphX

A graph computation engine for processing graph-structured data at scale. e.g., social networks, page rank.

📊 SparkR

A lightweight front end for R users to analyse large datasets and run jobs interactively from the R shell — R's usability + Spark's scalability.

🧠 Memory trick — 6 components
"Cool Students Stream Movies, Graphs & Reels" → Core · SQL · Streaming · MLlib · GraphX · SparkR. Core is the floor; the other five sit on top.

1.3Apache Spark terminology@@s1-3@@

SparkContext

The entry point of a Spark application. It connects to the Spark execution environment and is used to create RDDs, accumulators and broadcast variables, access Spark services, and run jobs.

Responsibilities of SparkContext

  1. Checking the current status of a Spark application
  2. Cancelling a job or a stage
  3. Running a job synchronously or asynchronously
  4. Accessing or unpersisting a cached RDD
  5. Programmable dynamic allocation of resources
🧠 Memory trick
"S C R A D" → Status · Cancel · Run · Access cache · Dynamic allocation — "Spark Can Run Any Data".
💻 Spark Shell

A Spark application written in Scala that gives you a command-line environment with auto-completion. Useful for getting familiar with Spark's features before writing a standalone application. (spark-shell for Scala, pyspark for Python.)

📦 Spark Application

A self-contained computation that runs user-supplied code to produce a result. It can have processes running on its behalf even when it is not actively running a job (its executors stay alive).

💡 SparkSession from textbook
From Spark 2.0, SparkSession is the single, unified entry point. It wraps the SparkContext (plus SQLContext and HiveContext). Get the context with spark.sparkContext.

Task, Job and Stage

🔹 Task

The smallest unit of work, sent to a single executor. Each partition of an RDD gets its own task.

🔷 Job

A parallel computation made up of multiple tasks, created in response to an action (e.g., count(), collect()).

🧱 Stage

A set of tasks within a job that depend on each other. A job is split into stages because not every computation can happen in one pass — some steps must wait for others (e.g., a shuffle) to finish first.

Figure 1.3 — An action creates a job; the job is split into stages; each stage runs many tasks
🧠 Memory trick — size order
Application ⊃ Job ⊃ Stage ⊃ Task — "All Jobs Split into Tasks". An application can run many jobs; each action = one job.
⚠️ Don't confuse with Hadoop (Unit 2)
In Hadoop, a job = one map phase + one reduce phase. In Spark, a job is triggered by an action and can have many stages — so one Spark job can do the work of several chained MapReduce jobs.

1.4Internal working of Spark — master/slave@@s1-4@@

🗣 In simple words
Think of a restaurant. The driver is the head chef who reads the order (your program) and plans the work. The executors are the cooks who actually chop and cook (process data). The cluster manager is the restaurant manager who decides how many cooks and stoves each head chef gets.
  • Similar to Hadoop, Spark also uses a master–slave architecture: one master and many slaves.
  • The driver is the central coordinator.
  • The driver and each executor run in their own Java process. Drivers handle a large number of executors; each executor works as a separate Java process.
  • A Spark application is a collaboration of a driver and its executors.
  • Spark has its own cluster manager, the standalone cluster manager. It can also work with open-source cluster managers like YARN and Mesos.

Each part in detail

🧠 Driver Program
  • A process that runs the main() function of the application and creates the SparkContext object.
  • The purpose of SparkContext is to coordinate applications, running as independent sets of processes on a cluster.
  • Can run in client mode or cluster mode on different types of cluster managers.
  • Tasks it performs: (1) it requires user code or methods to be cleaned (prepared to ship); (2) then it works over the application code to process it. The application code can be given as JAR or Python files passed to the SparkContext.
🧭 Cluster Manager
  • Its role is to allocate resources across applications.
  • Spark is capable of running on a large number of clusters.
  • Various types: Hadoop YARN, Apache Mesos and Standalone Scheduler.
  • The Standalone Scheduler is a standalone Spark cluster manager that makes it easy to install Spark on an empty set of machines.
🖥 Worker Node
  • The worker node is a slave node.
  • Its role is to run the application code in the cluster.
👷 Executor
  • A process launched for an application on a worker node.
  • It runs tasks and keeps data in memory or disk storage across them.
  • It reads and writes data to external sources.
  • Every application has its own executors.
🔹 Task

A unit of work that will be sent to one executor.

🧠 Memory trick — restaurant again
Driver = head chef (plans, creates SparkContext) · Cluster Manager = restaurant manager (gives out stoves) · Worker node = kitchen station · Executor = cook at that station (cooks + keeps ingredients ready = cache) · Task = one dish order.
⚠️ Common mistake
The cluster manager does not run your code and does not schedule tasks — it only gives resources (launches executors). Task scheduling is done by the driver.

1.6Internals of job execution in Spark@@s1-6@@

Figure 1.5 — Internals of job execution in Spark: Driver → SparkContext → DAG Scheduler → Task Scheduler → executors
  • 1The driver program creates a SparkSession/SparkContext and defines a chain of RDD operations (textFile → filter → map). Nothing runs yet.
  • 2When an action (e.g., count()) is encountered, a job is created.
  • 3The DAG Scheduler builds the operator DAG (graph of RDDs), splits the graph into stages of tasks, and submits each stage to the Task Scheduler as soon as it's ready.
  • 4The Task Scheduler launches the tasks via the cluster manager onto executors.
  • 5The cluster manager allocates resources and instructs workers to execute the job; it tracks submitted jobs and reports back their status.
  • 6The application code (JAR files) and configured dependencies are sent to the executors on worker nodes, which run the tasks.
🔑 DAG = Directed Acyclic Graph
A graph of steps with arrows that only go forward (no loops). Spark records your operations as a DAG first, optimises it, then runs it — this is why Spark can combine many steps into one stage and be faster than MapReduce.

1.7Run-time architecture of a Spark application@@s1-7@@

🗣 In simple words
From start to end: the driver asks for workers, the workers report for duty, the driver turns your code into a plan of stages and tasks, sends the tasks out, watches them run, and when you call stop() it sends everyone home and gives the resources back.
Figure 1.6 — Run-time flow of a Spark application (10 steps)
  • 1The driver talks to the cluster manager and negotiates for resources.
  • 2The cluster manager launches executors on behalf of the driver.
  • 3The executors register themselves with the driver.
  • 4When a job enters, the driver converts the code into a logical directed acyclic graph (DAG).
  • 5The DAG is optimised.
  • 6It is turned into a physical execution plan with a set of stages.
  • 7Small execution units known as tasks are created and sent to the cluster.
  • 8Executors execute all the tasks assigned by the driver. The driver monitors the executors that run.
  • 9The driver schedules future tasks by tracking the location of cached data (based on data placement) — so tasks run where their data already is.
  • 10When the program calls the stop() method of SparkContext, it terminates all executors and releases the resources from the cluster manager.
🧠 Memory trick — 10 steps
"N L R — L O P T — E M S": Negotiate · Launch · Register → Logical DAG · Optimise · Physical plan · Tasks → Execute · Monitor · Stop.
Story: "New Labourers Report; the boss Lists, Organises, Plans, gives Tasks; they Execute, he Monitors, then Says stop."
💡 Compare with Hadoop YARN (Unit 2)
The pattern is the same as YARN: ask for resources → start workers → run tasks → monitor → release. In Spark the driver plays the role that the ApplicationMaster plays in MapReduce on YARN. When Spark runs on YARN, the YARN ResourceManager is the cluster manager.

1.8Spark vs Hadoop MapReduce@@s1-8@@

A favourite exam comparison — it connects Unit 2 and Unit 3.

PointHadoop MapReduceApache Spark
ProcessingDisk-based — writes intermediate results to diskIn-memory — keeps intermediate data in RAM
SpeedSlowerUp to 100× faster in memory, ~10× on disk
Programming modelOnly map and reduceMany operations (map, filter, join, groupBy…) on RDDs/DataFrames
Execution planFixed: map → shuffle → reduceDAG of stages, optimised before running
Iterative / interactive workPoor (each iteration = new job + disk I/O)Excellent (data cached in memory; interactive shell)
Real-timeBatch onlyBatch + streaming (Spark Streaming)
LanguagesMainly JavaScala, Java, Python, R, SQL
LibrariesSeparate tools (Hive, Pig, Mahout…)Built-in: SQL, Streaming, MLlib, GraphX, SparkR
Cluster managerYARNStandalone, YARN, Mesos, Kubernetes
StorageHDFSNo storage of its own — reads from HDFS, local files, S3, HBase, Cassandra…
Master / workersJobTracker/TaskTracker (MR1); RM/AM/NM (YARN)Driver + executors (+ cluster manager)
⚠️ Common mistake
Spark does not replace HDFS — Spark is a processing engine, not a storage system. A very common setup is Spark on YARN reading from HDFS.
